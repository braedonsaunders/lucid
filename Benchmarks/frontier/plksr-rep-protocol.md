This resolves our earlier inability to find runnable weights in the organizer package. It does not establish that the exact downloaded checkpoint reproduces the organizer's reported score. Source and weights are pinned in `plksr-rep-preflight.json`; upstream code is MIT licensed and remains in the research checkout.

Reproduce the release's default FP32 inference: 64 channels, 12 blocks, 4× output, DCCM channel mixer, 17×17 partial convolution on one quarter of channels, elementwise attention, reflect padding by 16 source pixels and cropping by 64 output pixels. Strict-load every state entry. BasicSR is replaced only by registration and initialization shims; all initialized state is overwritten by the checkpoint. Native conversion uses the author's RepConv deployment folding and equivalent partial-convolution slicing. The original and deployed graphs agree within 0.00000364 on three deterministic small FP32 tensors. This is an equivalence preflight, not a video benchmark.

Compare shipping and interpolation controls on the same scorer backend. Keep the existing joint thresholds: at least 3% source-balanced LPIPS and DISTS improvements, no more than 2% perceptual regression per source, and no more than 0.01 fine-correlation loss per source. Use a fresh FP16 Core ML export from verified weights, compare against CPU FP32 with maximum/mean RGB error limits 3/0.6, and measure 20 predictions after ten warmups on four deterministic input images for CPU+GPU and CPU+ANE requests. ## Native precision check

The first harness invocation stopped because Core ML returned an RGBA PIL image; the comparison now explicitly extracts RGB, as Lucid's existing profiler does. It was a harness format error, not a network failure. The corrected FP16 run fails the unchanged maximum RGB threshold on CPU+GPU (max 5.4458, mean 0.26376) and CPU+ANE (max 48.0432, mean 0.93001). No latency samples are admitted for these inaccurate variants. A separate FP32 CPU+GPU export tests correctness and cost without choosing mixed-precision operations against quality results.

The FP32 CPU+GPU export passes the RGB limits (max 0.50084, mean 0.24874) but takes **296.90 ms mean / 297.54 ms p95** for 360p→1440p, before downsampling and delivery. This is not an efficient native video replacement on this M4 Pro. The released FP32 model is still being evaluated for quality as a possible training reference.
