# NVIDIA VFX SDK comparison preflight

September 5, 2026. NVIDIA publishes `nvidia-vfx==0.1.0.1` on its [own package index](https://pypi.nvidia.com/nvidia-vfx/), including a Windows Python 3.12 wheel. The [official Python API](https://docs.nvidia.com/maxine/vfx-python/latest/index.html) documents DLPack input/output and the `VideoSuperRes` effect. The [Comfy-Org node](https://github.com/Comfy-Org/Nvidia_RTX_Nodes_ComfyUI/tree/892515e3eb9a4920a131a502a047e47adca9eb0d) uses this package; no ComfyUI installation is required for our test. This rechecks the earlier unavailable SDK route using the public wheel, rather than assuming NGC access is mandatory for this binding.

The official wheel is downloaded directly and its published SHA-256 verified before extraction into a separate `C:\lucid\nvidia-vfx-baseline-20260905\deps` directory. The training environment has no pip module and is unchanged. Its metadata states that runtime libraries are bundled; successful inference still has to be demonstrated. No SDK binary or proprietary source is copied into Lucid or its Git repository.

Preflight uses a fixed seeded 640×360 RGB CUDA input, 1280×720 output, and the declared BICUBIC/HIGH/ULTRA modes. Require finite correctly shaped nonconstant output within the documented 0–1 range, and AI outputs distinguishable from the explicit bicubic mode. Copy returned SDK storage before the next call or close. Record versions, exact output hashes, load time, and twenty synchronized run-plus-clone samples after five warmups. No substitute scaler or exception fallback is allowed.

If this passes, score both HIGH and ULTRA on the same fixed 48 development pairs and report every mode independently. Do not pick the best mode after seeing quality and call it a prespecified result. Reset state between independent sampled images; this is an image-content screen, not a temporal or browser-driver VSR comparison. Use the existing source-balanced perceptual/detail metrics, pinned decoded inputs and shipping/interpolation controls. Native browser RTX parity and cross-hardware latency equivalence remain unestablished even if this SDK benchmark runs.

## Initial runtime finding

The hash-verified 490,396,952-byte Windows wheel loads SDK 1.2.0 on the RTX 4080 (driver 616.56). Bicubic inference returns valid nonconstant images and averages about 0.109 ms including clone/synchronization. The first probe exceeded its deadline after saving that row. A stage-instrumented repeat identifies the blocking call as `Effect.close()` → `_effect.destroy()`; repeated Python stack dumps confirm teardown rather than HIGH initialization. Only this experiment's process tree is terminated at the diagnostic deadline. No AI-mode claim follows from the bicubic result. The next isolated HIGH probe avoids earlier bicubic teardown and remains bounded.

## Isolated HIGH inference and image-screen lifecycle

An isolated HIGH probe returns finite, nonconstant 1280×720 output with a different hash and standard deviation from the identical seeded bicubic input. Its twenty warmed run-plus-clone samples average 0.539 ms (p95 0.548 ms) on the RTX 4080. It too blocks specifically in destroy(), as confirmed by stack traces; the owned process tree is terminated at its 60-second diagnostic deadline. This establishes execution of the selected HIGH API mode, not a completed three-mode preflight or a video-quality ranking.

For the image-content screen, use a fresh child process per input and mode. Each child synchronizes GPU work, clones the SDK output, writes its PNG and receipt, then exits the process without calling the known-blocking SDK destructor. The parent waits for process exit and bounds every child to 90 seconds; a timeout kills only that owned process tree and fails the screen. This lifecycle limitation is recorded explicitly. It is not a production SDK integration or a workaround applied to Lucid.

All BICUBIC, HIGH and ULTRA modes are evaluated on every one of the 48 frozen input PNGs. Reuse the already frozen native Core ML shipping RGB4× outputs with their declared PIL bicubic presentation adapter, verifying every output hash, and recompute all metrics on the same CUDA scorer. Include Lanczos. These comparisons use identical decoded RGB inputs; they exclude Lucid's downstream native NV12/detail and all browser presentation. Keep every mode result without selecting a winner from the evaluation set. The durable job waits for the current Lucid 960-pair scoring job to finish, then checks for other Python/GPU work before starting.
